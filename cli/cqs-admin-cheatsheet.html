A · Build, Package & Distribute

Build the bundles → pack a .tgz → install it on a machine with no npm access
🔧 Admin — Build & Distribute
# First-time setup — clone, then build
git clone https://github.com/mv-vasanth/\
  code-quality-studio.git
cd code-quality-studio/cli
npm install
npm run build:all
npm install -g .

# Create shareable tarball
npm run build && npm pack
# → cqs-audit-2.1.0.tgz

# Publish to npm (bump version first)
npm run build && npm publish --access public
⚙️ Bump version: edit "version" in package.json before rebuilding
📦 Install from .tgz (offline / internal)
# With admin rights
sudo npm install -g ./cqs-audit-2.1.0.tgz

# Without admin (no sudo)
npm install -g ./cqs-audit-2.1.0.tgz --prefix ~/.npm-global
echo 'export PATH="$HOME/.npm-global/bin:$PATH"' >> ~/.zshrc
source ~/.zshrc

# Windows
npm install -g .\cqs-audit-2.1.0.tgz
⚙️ Build Outputs & MCP Server
BUILD BOTH BUNDLES
# CLI + MCP server in one go
npm run build:all

# Or individually
npm run build
npm run build:mcp
ARTEFACTS PRODUCED
dist/cqs.js — the CLI (self-contained)
dist/cqs-mcp.js — the MCP server
VERSION IS AUTOMATIC
The build injects __CQS_VERSION__ from package.json. Bump the version there only — never edit the string in source.

B · Standalone Binaries, Local Dev & Project Rules

Ship cqs to machines with no Node · run the web app · enforce team rules in CI
🧊 Standalone Binary (no Node needed)
BUILD FOR THIS MACHINE
npm run build:binary
# → dist/bin/cqs-<platform>-<arch> (~107 MB)
⚠ USE AN NVM NODE TO BUILD
Some Node builds ship the SEA fuse string twice and injection fails. The build stops early and tells you.
export PATH="$HOME/.nvm/versions/\
  node/v22.22.3/bin:$PATH"
npm run build:binary
ALL PLATFORMS (CI)
SEA cannot cross-compile, so each target builds on its own runner. Push a v* tag:
git tag v2.1.0 && git push --tags
# .github/workflows/release-binaries.yml
Builds darwin-arm64 · darwin-x64 · linux-x64 · linux-arm64 · win32-x64, attaches them to the GitHub release with SHA256SUMS.
macOS quarantines downloads: xattr -d com.apple.quarantine cqs
💻 Run the Project Locally
WEB APP (VITE)
# from the repo root
npm install
npm run dev
# → http://localhost:5173
OTHER ROOT SCRIPTS
npm run build # production bundle
npm run preview # serve that build
npm run lint # eslint
CLI FROM SOURCE
cd cli
npm install && npm run build:all
npm install -g .
Offline by default. All 530 rules run locally — no telemetry, and the MCP server makes no network calls. Code is sent out only when you pass --ai.
📋 Project Rules (cqs-rules.json)
Committed next to your tests and discovered by walking up to the repo root — so CI and teammates get the same rules.
{
  "version": 1,
  "disabled": ["PW-SEL-002"],
  "rules": [{
    "id": "ACME-001",
    "stacks": ["playwright"],
    "category": "selectors",
    "severity": "critical",
    "title": "Use data-qa",
    "match": { "type": "regex",
      "pattern": "getByTestId\\(" }
  }]
}
CLI FLAGS
cqs ./tests/ --rules ./team-rules.json
cqs ./tests/ --no-rules
MCP TOOLS FOR RULES
cqs_list_rules — check coverage first
cqs_validate_rules — lint the file
cqs_test_rule — dry-run, show real matches
Invalid rules are reported and skipped — a typo never aborts the audit.
